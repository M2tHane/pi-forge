# 全局规则

（与 rules/<layer>.md 冲突时，以分层规则为准。）

## 完成与范围
1. 完成的定义：本 task 相关的测试全部通过，并且每条 AC 都能通过任务说明指定的验收入口演示；之后才能 forge_submit。
2. 实现与修复任务：需要改的文件直接改（例如路由注册入口）；别的任务负责的文件只做必要的最小改动，在 handoff 里写明。PRD、原型、契约与架构文档不能改。其他角色只改可写范围内的文件，需要越界时用 forge_block 说明原因。
3. 只实现 AC 要求的内容，不顺手添加"以后可能用到"的功能、参数或抽象。
4. 接口、字段、状态码、错误码以 docs/contracts/ 为准。契约要改时调用 forge_ask_architect（没有这个工具时用 forge_block 说明），不自己改。
5. PRD 有歧义时，有合理的默认做法就按默认做，并写进 forge_submit 的 deviations；会改变功能范围的，才用 forge_block，写明两种理解及各自的影响。
6. 新增依赖只加本 task 确实需要的，并在 handoff 中写明；不升级、不删除别的 task 在用的依赖。

## 测试
7. 不删除、不跳过、不放宽失败的测试；测试失败就修代码。验收测试由开发者自己写（任务说明『验收测试（由你编写）』一节），只写自己 task 的目录，由 reviewer 审查；不修改别的 task 的验收测试。
8. 测试期望值来自 PRD、契约或已知正确的例子，不用和被测代码相同的算法去算。
9. 只在系统边界上 mock（外部 API、时间、随机数）；不 mock 自己写的模块。

## 代码质量
10. 不静默吞掉错误：不允许空的 catch 或 except；捕获后要么处理，要么记录上下文后继续抛出。
11. 调用外部服务、文件系统、数据库时处理失败情况；错误信息带上关键参数，但不含密钥和个人信息。
12. 所有读写数据的入口都按 PRD 的用户与角色（openapi.yaml 的 `x-roles`）检查权限，不依赖前端隐藏按钮。
13. 不修改与本 task 无关、自己不了解的代码；确实需要修改时，在 handoff 中说明理由。
14. 单个文件超过 800 行时考虑按职责拆分，超过 1500 行必须拆分。

## 运行环境
15. 不把命令放到后台运行（&、nohup、setsid）；需要启动服务时，在同一条命令里启动、调用、停止，或者给命令设置超时。
16. 不启动桌面应用，不打开浏览器（只有批次验收的 stage-qa 用无界面浏览器）。需要用户打开查看的内容，写进 handoff。
17. 不在代码中写入密钥、令牌、个人信息；配置项从环境变量或配置文件读取。不读取 .env*、*.pem、secrets/**。

## 文件与交接
18. 新文件按用途放到 docs/arch/overview.md 约定的目录；不在仓库根目录随意新建文件；不创建空壳或占位文件。
19. 文本文件统一使用 UTF-8；发现乱码先修复，不在乱码文件上继续写入。
20. handoff（forge_note）写四段：做到哪、下一步、踩过的坑、未决问题。对以后的 task 也有用的经验，用 forge_learn 记入知识库。
21. 用 notes 维护笔记（目标、已完成、待完成、当前进度、决策、坑）；上下文被压缩后靠笔记继续，更早的细节用 history 检索。
